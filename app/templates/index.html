User manual

End-to-end: from "we just bought these stones" to "they're in EZ JEMS". Takes about 5 minutes for a batch of 15 stones.

Before you start

You need two things:

  • The X-API-Key for this app (saved in your password manager when you deployed it)
  • The AGL Report Numbers + Passwords for the stones you're importing (same ones you'd use at aglthai.com/report_check.php)

Steps

1

Download the intake template

Go to the intake.py tab and click "Download blank template". You'll get gs_purchase_intake_template.xlsx with the right column headers.

2

Fill one row per stone

Open the template in Excel. One row per stone you're adding. Columns:

  • Report No — AGL report number exactly as shown on the cert
  • Password — the lookup password AGL sent (digits only; "PASS 0998" is fine, the server extracts the digits)
  • Unit Price — per carat, in whichever currency the whole batch uses (don't mix currencies in one file)
  • FWD LOC — forward location for this stone (varies per stone)
  • FWD SSP — forward SSP for this stone (varies per stone)
  • Lot No — optional; leave blank if not using
Tip: Delete the example row before you add yours.
3

Upload the file

Back on the intake.py tab, paste your X-API-Key if prompted. Then drag the Excel file onto the drop zone (or click to browse).

The file name will appear in a pill confirming it's loaded.

4

Click Generate & wait

Click Generate import file. Expect ~3 seconds per row (2s polite delay to AGL + Gemini latency). A batch of 15 stones takes about 45 seconds; a batch of 50 takes about 2.5 minutes.

Don't close the tab while it's processing.

5

Review the row statuses

When processing finishes, you'll see 3 stat cards — OK / Amber / Red — and a table below listing every row.

OK

Every field extracted + mapped cleanly. Safe to import as-is.

Amber (review)

Row is written to the output but one or more fields need checking. The Warnings column says what's off; the __Raw AGL * side columns in the output file carry the original cert values for reference.

Red (skipped)

Row is not written to the output. Usually a bad Report No / Password, or AGL couldn't return the cert. Fix the intake row and re-run.

6

Download the import file

Click Download .xlsx. You'll get ezjems_bulk_import.xlsx.

7

Fix amber rows (if any)

Open the downloaded file in Excel. Any amber row will have the problem field blank (or holding an unmapped value) — look at the __Status and __Warnings columns on the far right.

Common amber cases:

  • Unmapped colour phrase (e.g. a rare descriptor Sonesh hasn't added yet) → type the right 3-letter code into the Color cell
  • Unmapped stone variety → type the ST and fix the Item # prefix

Delete the __Status, __Warnings, and __Raw AGL * columns before importing (optional — EZ JEMS ignores them, but your file will be cleaner).

8

Import into EZ JEMS

In EZ JEMS, open the bulk purchase-intake import screen. Pick the currency that matches your intake file. Upload the .xlsx.

Done — your stones are in the ERP with Item #s, measurements, colour codes, and FWD values populated.

Troubleshooting

?

"server missing GEMINI_API_KEY"

The Gemini key secret isn't set on the server. In PowerShell on the deploying machine: fly secrets set GEMINI_API_KEY="your-key", then fly deploy.

?

"AGL fetch failed: no report image"

The Report No / Password combo didn't match on aglthai.com. Fix the intake row — remember passwords are digits-only, and the Report No must match exactly (dashes, spaces, letters all preserved).

?

"vision extract failed"

Gemini couldn't read the cert image. Usually a transient network blip — just re-run. If it persists, check the Gemini key hasn't been rate-limited or revoked at aistudio.google.com/apikey.

?

"unauthorized (bad or missing X-API-Key)"

The X-API-Key field is empty or wrong. Paste the value from your password manager — it's a 48-char hex string.

About this module

Automates gemstone purchase intake into the EZ JEMS ERP. Built to replace the manager's manual field-by-field data entry off every AGL certificate.

What it does

For each stone in the intake Excel:

  1. Posts Report No + Password to aglthai.com's Report Check form (ports Certificate-Scrapper's lookup, 2s rate-limited).
  2. Sends the returned cert image to Google Gemini for structured field extraction.
  3. Maps AGL wording → EZ JEMS values via editable glossaries (variety → ST, shape → 3-letter + 2-digit codes, colour collapsing, OCT→EME override).
  4. Generates the Item # using BULK PI GENERATOR's gemstone convention ({ST}{shape}{colour}{measurement}).
  5. Writes a 29-column file matching GS_BULK_IMPORT.xlsx plus 7 side columns the ERP ignores (__Status, __Warnings, __Raw AGL *).

Sonesh master-data decisions baked in (2026-11-09)

Unit Price

Per carat (passed through unchanged).

Currency

Per-import setting at ERP side. One output file = one currency.

Report No

Required for every intake row.

ST column

3-letter short code (matches Item # prefix).

FWD LOC / FWD SSP

Vary per stone — fill per-row.

Inv Effect

Constant 1 for every row.

Treatment + Origin

Not tracked at ERP intake. Preserved in __Raw AGL * side columns.

Diamond intake

Out of scope. Gemstones only.
