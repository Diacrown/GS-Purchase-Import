## 2. Massive overlap with BULK PI GENERATOR

The new intake tool is essentially **BULK PI GENERATOR with an AGL front-end**.
Already solved in BULK PI and reusable as-is:

- Item # generation for Round + fancy shapes (ST + shape + colour + measurement)
- `SBK = "A"` forcing
- `IT = "PP"` rule + the overseas-client-name skip (will almost never apply here,
  but keep it for safety)
- Shape 3-letter codes: RND/OVL/CUS/EME/PSH/MQS/HRT/PRN/… and the OCT→EME override
- Colour 3-letter codes: BLU/RED/PPL/YLO/PNK/GRN/WHT/BLK/ORG/BRN

New work is small:
1. Call the AGL fetcher's JSON extractor per Report No (Step 1 — delivered).
2. Normalise AGL fields → map to ERP values via the glossaries (§3–§6).
3. Feed the normalised row into BULK PI's existing `buildGemstoneCode` to
   generate Item #.
4. Append the constants.
5. Write to the EZ JEMS template format.

## 7. Open items — blockers before build

Send to Sonesh / System Plus as one message:

1. **Unit Price**: per-carat or total? (`300` against `0.78 ct` is ambiguous.
   Hand-enter one stone round-trip and check an export, OR ask directly.)
2. **Currency**: template has no currency column. What currency does the ERP
   assume for `Unit Price`? Is there a global import-currency setting?
   Imports can be in USD, EUR, INR, THB — this must be resolved before any
   row is imported or every foreign-currency cost gets silently misread.
3. **Report No** is blank in the sample row. Is it actually required /
   imported by the ERP for AGL stones? (If not, the entire AGL-fetch step
   doesn't influence what the ERP stores, and the tool's role shrinks.)
4. **ST column** — what is it, and does it duplicate the Item# prefix?
5. **FWD LOC / FWD SSP / Inv Effect** — constants for every intake row at
   every office? Or do they vary by location / supplier?
6. **Treatment and Origin** — where do they land in EZ JEMS? Are there
   columns not shown in this template, or do they go in `Remarks`?
7. **Diamond intakes** — this template is positioned as GS (gemstone). Does
   System Plus have a separate diamond intake template, or the same template
   with the diamond-only columns (Cut, D%, Fluo, Pol, Sym, T%) populated?

## 8. Row-level failure policy (matches BULK PI GENERATOR convention)

The tool never silently writes a blank into EZ JEMS. For each AGL lookup:

- `extraction_status == "ok"` + all glossaries hit → full mapped row written.
- `extraction_status == "partial"` → row written with blanks in missing
  fields, row flagged amber with `missing_fields` listed in a side column.
- `extraction_status == "failed"` → row flagged red, skipped from the
  export (manager re-fetches or enters by hand).
- Any field whose glossary lookup has no match → row flagged amber, raw AGL
  value preserved in a side column so the manager can fix inline.
